# Tasks

The words of the design section "Terms" have the meaning that it gives: the store, the service thread, a window, the app window, the shown Series, a snapshot and the others. A request is a message from the app window to the service thread (design H5).

Paths are relative to the repository root. Each source or document path in a task has the marker "create" or "modify". A test file has the words "the new test file" in the task that creates it. Each other test file in a Verify part exists, and the task adds its tests to it. A test name with no mark is a test that the task creates. A test marked "(existing)" exists already and must still pass. A test marked "(existing, modified)" exists and the task changes it. More than one task can change it. Each new test name belongs to one task only.

This change depends on `add-nicecooling-v1`: its history store (`crates/nicecooling/src/history/`), its History and Settings screens and its app settings (`docs/storage.md`). All code of this change is in `crates/nicecooling`. No task changes `crates/nicecoolingd`, `crates/nicecooling-api` or `crates/nicecooling-core`.

Two other changes are on `main` next to this one: `add-node-graph` and `add-dashboard-pages`. The design section "Order with the other changes" names each shared file. A task reads a shared file as it is on `main` when the task starts, and keeps what the other changes put there. A task that changes a type or a function also changes each caller that the other changes added. The tasks 1.3, 1.4, 1.8 and 2.2 name these callers.

A task marked MANUAL needs a person on the reference desktop. The person follows a procedure file in `docs/hardware-checks/`. The file lists steps, the result that the person sees, and one pass or fail line per step. A MANUAL task passes when every step has a pass line.

Each section ends with a checkpoint task. The checkpoint command is:
`cargo test --workspace && cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --all --check && python3 -I tools/re/check-identifiers.py && openspec validate add-history-export --strict`.

Strings of the app go in `crates/nicecooling/locales/en.yml`, `crates/nicecooling/locales/it.yml`, `crates/nicecooling/locales/de.yml` and `crates/nicecooling/locales/fr.yml` with the task that uses them. "The four locale files" in a task means these four files, with the marker "modify". A string uses the terms of `docs/i18n-terms.md`. Task 1.1 adds the terms of this change. The tests `every_key_has_every_language`, `every_language_keeps_the_order_of_the_keys` and `every_key_used_in_source_exists` in `crates/nicecooling/tests/i18n.rs` (existing) check them.

The logic of the store is in `crates/nicecooling/src/history/` and has no GPUI type. A screen model is in `crates/nicecooling/src/screens/<name>.rs` and its view in `<name>_view.rs`. A new text input of a screen needs a variant of `InputKey` in `crates/nicecooling/src/screen_view.rs` and an arm of `on_input` in `crates/nicecooling/src/screens/handlers.rs`. A new integration test file of the app is under `crates/nicecooling/tests/`. A test of the store uses a database in a scratch directory or in memory, and a simulated time.
