# Tasks

Each task names its crate and its files. Each task ends with "Verify:" and a pass criterion. Paths are relative to the repository root. A crate name stands for `crates/<name>`.

`crates/nicecooling-api/dbus/io.github.cappyt.NiceCooling1.xml` and `docs/api.md` define the D-Bus API. `docs/storage.md` defines the stored files. Tasks cite them and do not change them, except task 4.5, which adds the `busctl` examples section to `docs/api.md`.

A task marked MANUAL needs a person on the reference desktop. The person follows a procedure file in `docs/hardware-checks/`. The file lists steps, expected results and one pass or fail line per step. A MANUAL task passes when every step has a pass line. A check that a container can run is automated.

Each section ends with a checkpoint task. Section 2 ends with a gate.

  1. Read the value table.
  2. Compute Derived sensors and calibrated flows.
  3. Evaluate the Alarms. A stub ships here. Tasks 6.x replace it.
  4. Evaluate the Rule groups. A stub ships here. Tasks 7.x replace it.
