## Resolution

Category: FIX (applied without changing an owner decision), DECISION (owner answer, 2026-11-22), ACCEPTED (owner accepts the risk), NOT ADOPTED (with reason).

- **C1. FIX.** D6 becomes a failure model. One task per source (each hwmon chip, the Leakshield HID interface, the Leakshield bulk interface) publishes timestamped values. The safety tick reads only that snapshot and never waits on I/O. A value older than 3 s counts as no value, so the Lost Input rule covers a stuck device. Leakshield setting writes run in a separate worker with a queue of one. systemd: `Type=notify`, `WatchdogSec=10s` fed only after the safety stages, `Restart=on-failure`, `StartLimitBurst`; `ExecStopPost` restores the BIOS snapshot. The app shows "daemon down, Board on BIOS curves" when the restart limit is reached.
- **C2. FIX.** D6 lists the tick as numbered stages: snapshot; Derived sensors and calibrated flow; Alarm evaluation; Profile rule evaluation; Curves with Input smoothing; Duty step limit; Pump floor; overrides (Lost Input, pump stop) that bypass the step limit; reconcile and write; Feed message; watchdog ping. Pump stop takes every Channel, Hardware-curve Channels included; when it closes, Channels without a Curve or fixed Duty get their BIOS snapshot attributes back. Pump stop is raised when any Pump channel of a Loop reads 0 rpm for 5 s while its Duty (for a Channel on its Hardware curve: the current `pwmN` value) is above zero; it closes when every Pump channel of the Loop reads more than 0 rpm for 10 s.
- **C3. FIX.** Each tick reads back `pwmN` and `pwmN_enable` and writes when the raw 0-255 value differs from the desired one. Three mismatches in 60 s raise an "another writer" Warning. The resume rule is deleted.
- **C4. DECISION + FIX.** New Alarm "Leakshield unreachable": no report 1 or a failed Feed message for 10 s, debounced; default response notify. Reattach on udev events matched by USB path. The out-of-tree `aquacomputer_d5next` driver from GitHub (aleksamagicka/aquacomputer_d5next-hwmon) also sends the Feed message: documented as a conflict and a risk. Open Question plus RE task: Leakshield behavior when the Feed stops.
- **C5. DECISION.** The RPM ships a drop-in for `poweroff.target`: `JobTimeoutSec=60s`, `JobTimeoutAction=poweroff-force`. Every shutdown that takes more than 60 s becomes forced. Goal: from the end of the alarm delay to power off in at most 60 s. A daemon restart during a countdown restarts the countdown if the Alarm is still active.
- **C6. FIX.** Alarm notifications use critical urgency; the app checks the `actions` capability of the notification server; "Cancel poweroff" is also in the tray menu and the window. Any session's app can cancel. New task: a spike that proves a windowless GPUI process with a StatusNotifierItem and notification actions, and records its idle CPU and RAM.
- **C7. ACCEPTED.** The polkit policy stays: writes are free for a `wheel` member in the active local session, also when they lower an alarm response, the Pump floor or a pump Duty. Recorded in Risks.
- **C8. DECISION.** Profile switching on the Leakshield follows aquasuite. Until the decompiled code shows how aquasuite applies device profiles, the current specs stay: full snapshot, Maintenance pause, Rule delay, Profile dwell, Immediate switching. New RE task: document how aquasuite applies device profiles (fields written, Mode handling, rate limits, automatic switching) and align the profiles spec; report differences to the owner. FIX: when the Leakshield part of a switch fails its read-back, the Profile shows "Curves applied, Leakshield failed" with the restore offer. Risk entry: unknown write endurance of the device settings.
- **C9. FIX.** A Profile rule activates its Profile only when it becomes the winning rule, not on every tick.
- **C10. DECISION + FIX.** A Default Profile always exists and cannot be deleted. It is active when no rule wins and no manual activation exists; changes made then go into it. Each rule has its own Rule delay timer; the winner is the first rule in list order whose condition has held for its Rule delay.
- **C11. DECISION.** Suspend Profile rules are out of v1. Resume is covered by C3.
- **C12. DECISION.** Verification is a development-time procedure on the reference Leakshield: plausible reads on the fixtures and supervised Verification writes in the manual hardware-check tasks. The result is static registry data per model and firmware version. The app has no Verification write action and no runtime ledger. An unknown firmware version is read-only. The firmware version is in report 1, bytes 13-14 (measured on fw1019). Layout reuse for unknown firmware is NOT ADOPTED (speculative). ADR-0001 and the glossary change accordingly.
- **C13. DECISION + FIX.** Daemon-owned state in `/var/lib/nicecooling/`: atomic write (temporary file, fsync, rename), schema version, last-known-good copy, each Profile in one place with its Leakshield snapshot. No hand-edited configuration file. The Curve editor applies live in memory; the daemon persists on drag end or after a 2 s debounce.
- **C14. DECISION.** Experimental devices are out of v1: delete the `experimental-devices` capability, D14, task group 9 and the glossary term. ADR-0004 records that other Aqua Computer devices are out of v1. Their sensors still appear through generic hwmon discovery when the kernel driver exposes them.
- **C15. DECISION.** nicecooling keeps the full fan-control stack; code may be taken from CoolerControl. New ADR-0008 records the reason (one daemon couples Pump floor, Feed, pump stop, Leakshield Inputs and Profiles; one app) and the rejected option (Leakshield-only daemon next to CoolerControl). License compatibility with CoolerControl (GPL-3.0) is an open item before any distribution.
- **C16. FIX.** The write path re-reads report 3 just before the write and aborts on an unexpected change. The registry holds a mask of bytes that the device changes by itself; the read-back compare and the external change detection both use it. The CRC bytes are expected to change. Backups keep reports 3, 5 and 8, but restore writes only report 3 until 5 and 8 are decoded. Retention: the first backup per serial plus the last 20, deduplicated by hash. The write path of display assets is an Open Question for the RE.
- **C17. FIX.** The daemon reads report 3 every 10 s and compares it with the last known value outside the volatile mask; after its own verified write it updates the last known value. A difference is an external change.
- **C18. FIX.** Manual mode is `pwmN_enable` = 1. The daemon writes a takeover lease file before the first manual write and removes it only after a restore whose read-back matches the snapshot; it refreshes the snapshot only when no lease exists. On first start with a Channel already in manual mode, it takes the snapshot anyway, marks that Channel "manual at snapshot" and raises a Warning.
- **C19. FIX.** design.md defines inline, in one line each, the terms its safety decisions use. Glossary: Warning and Alarm also cover nicecooling events; new terms "alarm response" (none, notify, poweroff after a delay), "Feed message" (the transport), "fixed Duty"; the Action term stays only for Leakshield procedures. One spelling: rpm.
- **C20. FIX.** Goals: "Write only Verified fields." Measurable goal: without a user session the daemon runs the Curves, sends the Feed, evaluates the Alarms and runs the alarm responses; from the end of the alarm delay to power off in at most 60 s.
- **C21. FIX.** Each hard-to-reverse decision gets one rejected alternative with its reason. The out-of-tree driver is named as the reference for the Feed message codec and its golden tests; the proposal says `nusb` instead of libusb.
- **C22. FIX.** Risks add: wheel writes without a prompt (C7), local read access, a root daemon that parses USB input, the legal basis (interoperability, Directive 2009/24/EC, Article 6), Feed stop, disconnect during a write, missing or corrupt BIOS snapshot. Line 12 vs 98: aquasuite and its service never run. The workstation details move out of the design; D1 keeps outputs and boundary.
- **C23. FIX.** Rollback: stop the service (BIOS snapshot restored), restore the first Leakshield backup if wanted, remove the RPM; list the leftover files in `/var/lib/nicecooling/` and the polkit rule.
- **C24. FIX.** Short decisions for: Board file format and location, Derived sensors, GPU Inputs, Mode and Action transport (RE), Software sensor values in the Feed message (RE), Refill refusal when the Pump channel reads above 0 rpm, device clock, device alarm settings proposals (cite ADR-0007), localization, history aggregation, daemon unreachable.
- **C25. FIX.** Risk entry with an estimate: about 60 sensors at 1 Hz; the app writes in batches every 10 s and prunes hourly.
- **C26. FIX.** Rewrite in ASD-STE100 style with numbered lists for the tick and a table for polkit; decisions in capability order.
- **C27. NOT ADOPTED.** The difference type costs little and the owner can add an air probe later.
- **C28. NOT ADOPTED in the design.** A hardware watchdog is a host setting, listed as optional in the docs.
- **C29. NOT ADOPTED.** A flow-loss Alarm was not requested; process rule names are low-risk local data (recorded in Risks).
