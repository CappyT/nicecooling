# Tasks

Each task names its crate and its files. Each task ends with "Verify:" and a pass criterion. Paths are relative to the repository root. A crate name stands for `crates/<name>`.

This change depends on `add-nicecooling-v1`: it reads its contracts (`docs/api.md`, `docs/storage.md`, the XML) and changes them only where a task says so.

A task marked MANUAL needs a person on the reference desktop. The person follows a procedure file in `docs/hardware-checks/`. The file lists steps, expected results and one pass or fail line per step. A MANUAL task passes when every step has a pass line. A check that a container can run is automated.

Hard rule for every task: tests use the simulated bootloader. No test and no tool of this change opens the real device. Only the two MANUAL checks of sections 1 and 7 touch it, and the capture of section 1 only watches aquasuite.

Run `spec-review` on this change before section 2 starts. Each section ends with a checkpoint task. Section 1 ends with a gate.

## 1. Capture of the aquasuite update and the open decisions

- [ ] 1.1 Write `docs/hardware-checks/firmware-update-capture.md`: a supervised aquasuite update in the VM `win11-aquasuite` with a host `usbmon` capture. Steps: load `usbmon`, find the bus of the device, start the capture with `dumpcap` on `usbmon<N>`, start the re-attach watcher of `docs/hardware-checks/firmware-update.md`, run the update, stop both, save the capture to `re/captures/` (git ignores `re/`). Run 1: aquasuite in German, device in English, so aquasuite flashes the DE image. Run 2: aquasuite in English, so it flashes the EN image and restores the device. Each step has an expected result and a pass or fail line. The file states that the loop must be closed and that the leak protection is off during the update. Verify: `rg -c '^Pass:' docs/hardware-checks/firmware-update-capture.md` prints the step count, and the file names both runs.
- [ ] 1.2 Write `tools/re/usbmon-summary.py` and the sample `tests/fixtures/usbmon-sample/capture.json` (a few synthetic transfers). The tool reads the output of `tshark -r <capture> -T json` and prints: the HID report descriptor of the bootloader (`wLength` of report 32), each SET_REPORT with its `wLength`, its status (ACK, STALL or timeout) and its time, the first 32 bytes of the first chunk, the time from the restart command to the new enumeration, the time from the last command to the application enumeration, and every report 1 of the bootloader with its length. It only reads files. Verify: `python3 -I tools/re/usbmon-summary.py tests/fixtures/usbmon-sample/capture.json` exits 0 and prints each of these items for the sample, and `rg -n 'hidraw|usb.core|open\(' tools/re/usbmon-summary.py` finds only the open of the input file.
- [ ] 1.3 MANUAL: run 1 of the capture (aquasuite in German, DE image). Procedure: `docs/hardware-checks/firmware-update-capture.md`. Verify: every step of run 1 has a pass line, the capture file exists in `re/captures/`, and report 1 bytes 13-14 read 0x03 0xFE and byte 34 reads 1 (German) afterwards.
- [ ] 1.4 MANUAL: run 2 of the capture (aquasuite in English, EN image). Procedure: the same file. Verify: every step of run 2 has a pass line, the capture file exists, and report 1 bytes 13-14 read 0x03 0xFE and byte 34 reads 0 (English) afterwards.
- [ ] 1.5 Record the results in `docs/re/firmware-update.md`. For each row of the table "Open points and checks", write the measured value or "not observed", with the capture file name and the summary tool output. Set these values: the length of feature report 32 in the bootloader, the status of each chunk, the time to enter and to leave the bootloader, frame bytes 1-7, and the report 1 of the bootloader (its length, and whether it holds the serial, the hardware and the bootloader version). Verify: `rg -c 'unknown' docs/re/firmware-update.md` counts only statements that the capture cannot settle, and each such statement names the reason.
- [ ] 1.6 Gate. The owner reviews task 1.5 and answers the open questions of `design.md` that the capture leaves open. The planner then updates the spec, `design.md` and the tasks 2.2, 4.x and 7.x. Do not start section 4 before this gate passes. Sections 2, 3, 5 and 6 do not depend on it, except where a task says so. Verify: the owner approves in the thread, `design.md` lists only unanswered open questions, and `openspec validate add-leakshield-firmware-update --strict` exits 0.
- [ ] 1.7 Settle the v1 text that says nicecooling does not update firmware . The change goes into the v1 change before its archive: drop the requirement there. Files that carry the text: the requirement "No firmware update" in `openspec/changes/add-nicecooling-v1/specs/leakshield-settings/spec.md`, the "Unknown firmware" row of `docs/ui/screens/leakshield-system.md`, the first paragraph of `docs/hardware-checks/firmware-update.md` and `docs/adr/0004-scope-leakshield-features-and-other-devices.md`. ## 2. Image, frame and simulated bootloader (nicecooling-protocol)

- [ ] 2.1 Implement the image container. File: `crates/nicecooling-protocol/src/firmware/image.rs`, `src/firmware/mod.rs`. Parse the XML with `roxmltree` and the data with `base64`. Both are in `Cargo.lock`: pin them in the `Cargo.toml` of the crate at the locked versions. The parser refuses a document without segments, bad base64, a segment below 0x4000, overlapping segments and more than 1 MiB. The tests build their containers in code and ship no firmware. Verify: tests `parses_two_segments`, `refuses_no_segment`, `refuses_bad_base64`, `refuses_segment_below_0x4000`, `refuses_overlap`, `refuses_oversize` and `bom_is_accepted` pass, and `cargo tree -p nicecooling-protocol --depth 1` lists `roxmltree` and `base64` at the locked versions.
- [ ] 2.2 Implement the chunks and the report 32 frame. File: `crates/nicecooling-protocol/src/firmware/frame.rs`. Constants and layout follow design D5. The builder takes the feature report length. Use the CRC function of `src/crc.rs`. After gate 1.6, set the default length to the measured one. Verify: tests `chunk_count_108_for_109952_bytes`, `last_chunk_padded_with_ff`, `addresses_step_1024_from_0x4000`, `frame_layout_bytes` (header `20 000000 00000002 00004000 00000400`), `crc_covers_bytes_after_id` and `frame_length_parameter_pads_or_refuses` pass.
- [ ] 2.3 Implement the bootloader state and the restart commands. File: `crates/nicecooling-protocol/src/firmware/bootloader.rs`. The restart commands are report 2 command 1 with parameter 1 (`02 00000001 00000001 F443`) and parameter 0 (`02 00000001 00000000 3482`). A report 1 with firmware 1 to 99 is a bootloader report. A short report is padded with zeros before the fields are read. A hardware or bootloader field of 0 is absent. Verify: tests `restart_into_bootloader_bytes`, `restart_plain_bytes`, `firmware_1_to_99_is_bootloader`, `firmware_1022_is_not`, `short_report_padded` and `zero_ids_are_absent` pass. `cargo test -p nicecooling-protocol` exits 0, and the note of the `restart` command in `registry/leakshield.toml` says "1: restart into the bootloader, 0: plain restart".
- [ ] 2.4 Implement the simulated bootloader. File: `crates/nicecooling-protocol/src/sim.rs` (behind the feature `sim`). Design D12 gives the modes and the configuration. The sim sends the re-enumeration events of the real device. It stores the chunks, checks length and CRC, and leaves the bootloader only with a complete image. Verify: tests `sim_enters_bootloader_on_restart_1`, `sim_rejects_bad_crc`, `sim_rejects_wrong_length`, `sim_complete_image_returns_new_firmware`, `sim_incomplete_image_stays_in_bootloader` and `sim_second_flash_recovers` pass.
- [ ] 2.5 Check the hard rule. Verify: `rg -n '/dev/hidraw|HIDIOCSFEATURE|nusb::list_devices' crates/*/tests tools` prints nothing for the firmware tests, and `rg -n 'firmware' tools/nicecooling-verify/src` prints nothing.
- [ ] 2.6 Checkpoint. Verify: `cargo test -p nicecooling-protocol` exits 0, and `cargo clippy -p nicecooling-protocol --all-targets -- -D warnings` and `python3 -I tools/re/check-identifiers.py` exit 0.
