# Tasks

Each task names its crate and its files. Each task ends with "Verify:" and a pass criterion. Paths are relative to the repository root. A crate name stands for `crates/<name>`. A test name in a task is a test that the task writes.

This change depends on `add-nicecooling-v1`: its D-Bus contract (`crates/nicecooling-api/dbus/io.github.cappyt.NiceCooling1.xml`, `docs/api.md`), its state store (`docs/storage.md`) and its control tick. Tasks of this change edit these files only where a task says so. The daemon gets no Graph code, no command runner and no network client in any group.

A task marked MANUAL needs a person on the reference desktop. The person follows a procedure file in `docs/hardware-checks/`. The file lists steps, expected results and one pass or fail line per step. A MANUAL task passes when every step has a pass line. A check that a container can run is automated.

Each group ends with a checkpoint task. The checkpoint command is:
`cargo test --workspace && cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --all --check && python3 -I tools/re/check-identifiers.py && openspec validate add-node-graph --strict`.

Group 9 holds the documents. The tests of groups 2 to 8 carry the behavior. The contract file of group 4 is the source that group 9 describes.
