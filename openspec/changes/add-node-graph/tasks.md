# Tasks

In this file, response means Graph response. A Graph with a sensor end node gives a Graph sensor. A Graph with a response end node gives a Graph response.

Paths are relative to the repository root. A crate name stands for `crates/<name>`. Each path in a task has the marker "create" or "modify". A test name in a task is a test that the task creates. A test marked "(existing)" exists already and must still pass. Each test name belongs to one task only.

This change depends on `add-nicecooling-v1`: its D-Bus contract (`crates/nicecooling-api/dbus/io.github.cappyt.NiceCooling1.xml`, `docs/api.md`), its state store (`docs/storage.md`) and its control tick. The daemon does not depend on `nicecooling-graph`. The daemon gets no Graph code, no command runner and no network client in any section.

A task marked MANUAL needs a person on the reference desktop. The person follows a procedure file in `docs/hardware-checks/`. The file lists steps, the result that the person sees, and one pass or fail line per step. A MANUAL task passes when every step has a pass line. A check that a container can run is automated.

Each section ends with a checkpoint task. The checkpoint command is:
`cargo test --workspace && cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --all --check && python3 -I tools/re/check-identifiers.py && openspec validate add-node-graph --strict`.

Strings of the app go in `crates/nicecooling/locales/en.yml` and `crates/nicecooling/locales/it.yml` with the task that uses them. The tests `every_key_has_every_language` and `every_key_used_in_source_exists` in `crates/nicecooling/tests/i18n.rs` (existing) check them.

The pure logic is in `crates/nicecooling-graph`. The tasks of the app connect it to the clock, the files, the D-Bus and logind. A new integration test file of the daemon is under `crates/nicecoolingd/tests/` and starts with `mod support;`. A new integration test file of the app is under `crates/nicecooling/tests/` and starts with `mod support;`.
